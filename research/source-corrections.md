# Source corrections and limits

This record prevents earlier conversational confidence from becoming unsupported publication authority. A correction is part of the research, not something to hide.

## The deprecated HumanLayer repository

Earlier recommendations pointed at `humanlayer/humanlayer` as a current implementation starting point. Its inspected README describes the code as deprecated. The current workflow analysis uses `humanlayer/skills`; the old repository remains a historical reference. See [S04](sources/index.md#s04).

## Make Clear session and installation claims

Earlier assistant messages suggested the original Codex discussion or local skill had been recovered more fully than the available evidence supports. The user's intent is available: text alone is sometimes insufficient; understanding is broader than approval; views should help challenge thinking. The original local skill source and complete Codex transcript were not retrieved for this edition. Installation, installer validation, local activation, and cross-agent discovery are not claimed as verified here.

## The Matt Pocock / Uncle Bob interview

The conversation referred to a particular interview and attributed several detailed practices to it. The exact recording and transcript were not independently verified in this preparation. The publication relies on Robert Martin's written Clean Architecture article for the claims it makes and leaves interview-specific attributions unresolved. A previously supplied video identifier is not treated as verification.

## PRD, TDD, and outline are not a universal mandatory sequence

The inspected RPI workflow supports several routes and shortcuts. A PRD can proceed to an outline or implementation when the needed decisions are settled. Our risk-adaptive workflow is therefore not an exception invented to repair an inherently rigid source. See [S01](sources/index.md#s01).

## Matt's specification is not product-only

The inspected `to-spec` skill includes implementation and testing decisions. The earlier contrast between Matt as product/prototype and Dex as technical design was too sharp. The book compares artifact ownership and workflow composition instead. See [S07](sources/index.md#s07).

## PStack approval is opt-in in the inspected architect skill

The skill defaults to proceeding after synthesis. Our required approval for consequential boundary changes is a deliberate adaptation, not its native default. We do not infer one universal approval rule for every PStack skill from this file. See [S08](sources/index.md#s08).

## Vertical slices were used loosely

A database-only or domain-only phase can be a useful preparatory task, but it is not necessarily a complete vertical slice. The worked outline uses demonstrable behaviors across the layers they need, and labels preparation separately.

## The ambiguous slop tool

SlopCodeBench is verified as a separate benchmark. A specific TypeScript utility called “Slop Scan” was not identified reliably. We do not invent a repository link or treat the benchmark as a drop-in CI linter. Benchmark claims are scoped to the inspected repository description, not every earlier numerical claim.

## Static types do not establish runtime access rights

A typed policy declaration can catch representational errors. It does not authenticate requests, prevent an unregistered entry point, or prove tenant isolation. The current model combines static declarations, inventory, runtime enforcement, and negative tests.

## Local validation does not prove the factory

The checks in this package validate documents, generated assets, typed examples, and a narrow in-memory behavior model. They do not demonstrate client outcomes, reduced supervision, production security, or long-term maintainability. Those questions remain in the experiment program.

## Archive scope

The archived blueprint and starter prompt are supplied historical artifacts. They may contain outdated links, unvalidated numerical assertions, or stricter defaults than the book. Their presence is not a renewed assertion that those claims are established. The archive banner makes that status explicit.
